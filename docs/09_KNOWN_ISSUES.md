# 09 · 已知问题与限制

本文档记录**当前版本解决不了的事**。写清楚边界，比假装没有更专业。

---

## A. 功能缺口

### A1. 正文不支持插图

**现象**：文章正文只能放文字、列表、引用、提示框，**不能放图片**。

**原因**：`data.js` 的正文块类型只有 7 种，没有 `img`。

**影响**：活动照片只能放在文章外面，或另开页面。

**解决方向**：增加一种块类型 `{ t: 'img', src: 'assets/img/xxx.jpg', cap: '图注' }`，
在 `app.js` 增加一个渲染分支。工作量约 1 小时。

---

### A2. 改内容需要碰代码文件

**现象**：加文章要编辑 `data.js`，少一个逗号整站白屏。

**原因**：没有后台，内容以 JavaScript 对象形式存储。

**影响**：非技术成员不敢改，实际上只有 1–2 人能维护。

**解决方向**：做一个 `admin.html` 表单页，填完生成代码块，复制粘贴即可。
工作量约半天。

---

### A3. 没有访问统计

**现象**：不知道有多少人访问、看了哪些页面。

**原因**：纯静态站，没有埋点；接入第三方统计会引入外部脚本，
与"零依赖、可离线"的设计冲突。

**影响**：中期材料里"使用效果"缺少量化证据。

**解决方向**：接入轻量统计（如 Umami 自建、或平台自带的 Insights），
接受一定的外部依赖。也可用"馆内导览机的实际操作次数"作为间接指标。

---

### A4. 廉洁AI 是词匹配，不是语义理解

**现象**：问"礼金"可能搜不到"红包"的条目；问法太口语化会落空。

**原因**：`ai.js` 用的是关键词加权，没有向量检索，也没有大模型。

**影响**：命中率依赖 `KB` 的 `tags` 写得够不够全。

**解决方向**：优先扩充 `tags`（成本低、见效快）；如需语义检索，
需要引入向量库或调用模型 API（会破坏"零依赖"）。

---

### A5. 没有登录与权限

**现象**：所有内容对所有人可见，无法做"仅成员可见"。

**原因**：静态站没有后端。

**影响**：内部材料（如未脱敏的问卷数据）不能放上去。

**说明**：这是**有意为之**——一旦引入权限，就需要服务器与账号体系，
维护成本会成倍上升。

---

## B. 依赖与外部限制

### B1. 依赖 GitHub 账号与公开仓库

- 网站依赖 `YbjCsu0429` 这个账号存在
- 仓库必须保持 **public**；改为私有，网站立即下线
- GitHub Pages 若调整政策，需要迁移（代码不用改）

### B2. 国内访问速度受网络影响

`github.io` 在国内多数网络可访问（实测约 1 秒），但**不保证任何网络都稳定**。

**建议**：开馆前用不同运营商手机实测。若普遍超过 3 秒，迁移到国内节点。

### B3. 推送必须带代理参数

本机有系统代理 `127.0.0.1:7892`，但 git 不读系统代理。
所有 `git push` 都要加 `-c http.proxy=http://127.0.0.1:7892`。

**换电脑时**：先确认那台机器是否需要代理。

### B4. 令牌只在本机

`.cache/gh_token.txt` 是明文文件，不随仓库备份。
换电脑需要重新生成令牌。

## C. 体验限制

### C1. 移动端为适配而非重设计

手机上能用，但版式是为桌面设计的简化版。没有做"移动优先"的重排。

### C2. 没有搜索历史与联想

搜索是即时过滤，不记录历史，不做输入联想。

### C3. 情景实训只有 3 个脚本

来自材料汇编，未新增。若要覆盖更多场景（如社团经费、网络言行），需要新写脚本。

## D. 明确不做的事

| 不做 | 原因 |
|---|---|
| 引入 React/Vue 等框架 | 现有规模下，维护成本高于收益 |
| 做后台 CMS | 需要服务器与长期维护，与"断网可用"冲突 |
| 做用户系统 | 同上 |
| 自动抓取外部内容 | 版权与准确性风险 |
| 代刷课程、代写作业 | 学术不端 |
