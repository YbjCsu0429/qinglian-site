# 05 · 内容编辑指南

面向不写代码的成员。按本文操作，不需要懂编程。

---

## 准备

1. 用 **VS Code** 或 **记事本** 打开 `assets/js/data.js`
2. **先复制一份备份**：`data.js` → `data.js.bak`
3. 改完保存，浏览器按 `F5` 刷新

> 改坏了怎么办：把 `.bak` 改回 `data.js`，刷新即恢复。

---

## 场景一：加一篇文章

### 步骤

1. 打开 `data.js`，搜索 `const ARTICLES`
2. 找到最后一条文章的结尾（`}` 后面跟 `]` 的地方）
3. 在 `}` 后面加一个英文逗号 `,`，然后粘贴下面的模板
4. 改内容，保存

### 模板

```js
  {
    id: 'a13',
    title: '文章标题',
    dim: '理论深度学习',
    jiu: '场馆研学践廉',
    tags: ['关键词1', '关键词2'],
    minutes: 5,
    excerpt: '卡片上显示的两行摘要，60 到 90 字。',
    body: [
      { t: 'p', c: '第一段正文。' },
      { t: 'h2', c: '小标题' },
      { t: 'p', c: '第二段正文。' },
      { t: 'ul', c: ['要点一', '要点二'] },
      { t: 'callout', c: '这句会被强调显示。' }
    ],
    source: '依据项目材料整理。'
  },
```

### 注意

| 项目 | 规则 |
|---|---|
| `id` | 不能与已有重复，接着 `a13`、`a14` 往下排 |
| `dim` | 只能是：理论深度学习 / 文化浸润熏陶 / 沉浸实践体验 / 数字科技赋能 |
| `jiu` | 通用文章填 `null`（不加引号） |
| 引号 | 一律英文单引号 `'`；正文里要引用时说 `“某某”`（中文双引号） |

## 场景二：加一个人物

```js
  {
    id: 'f9',
    name: '姓名',
    era: '朝代 · 生卒年',
    tag: '古代廉吏',
    seal: '姓',
    brief: '一句话概括，卡片上显示。',
    body: ['第一段', '第二段', '第三段'],
    lesson: '给我们的启示，一句话。'
  },
```

`seal` 只填**一个汉字**（通常是姓），会显示成红色印章。

**史实要求**：生卒年、官职、事件必须准确。拿不准的细节宁可删掉——写错一个年份，
比少写一段更伤。

## 场景三：加一条法规

```js
  {
    id: 'r11',
    name: '《法规名称》',
    scope: '适用对象',
    tag: '党内法规',
    points: ['要点一', '要点二', '要点三'],
    note: '具体条款以官方最新文本为准。'
  },
```

**不要写条文编号**（如"第三十二条"），除非你核对过原文。写错编号是硬伤，
只写要点不会错。

## 场景四：让廉洁AI 回答一个新问题

这是最常做的操作。找到 `const KB = [`，在末尾加：

```js
  { q: '问题怎么写', a: '答案正文，一百到两百字。', tags: ['关键词1', '同义词2'], link: '#/article/a13' },
```

### 三个提高命中率的技巧

**1. tags 放同义词**

```js
tags: ['红包', '礼金', '回扣', '好处费']   // ✅
tags: ['红包']                              // ❌ 用户说"礼金"就搜不到
```

**2. 一个概念拆成多条**

```
什么是微腐败
微腐败有哪些表现
微腐败和普通腐败的区别
```

**3. 答案第一句给结论**

用户往往只看第一句。不要铺垫，直接回答。

## 场景五：改一处文字

直接搜索原文，改掉即可。比如改首页大标题：

1. 搜索 `把廉洁`（在 `app.js` 里，不是 `data.js`）
2. 改成你要的句子
3. 保存刷新

> **注意**：首页标语、栏目描述这类"固定文案"在 `app.js` 里；
> 文章、人物、情景、法规、知识库在 `data.js` 里。

## 常见错误对照表

| 现象 | 原因 | 解决 |
|---|---|---|
| 页面全白 | 少了一个逗号 / 引号没配对 | 按 `F12` 看控制台，会指出行号 |
| 某篇文章点进去 404 | `JIU[].article` 指向了不存在的 id | 检查 id 拼写 |
| 卡片摘要显示不全 | `excerpt` 太长 | 压到 90 字以内 |
| 中文引号显示成方块 | 用了英文引号 `"` | 改成中文引号 `“”` |
| AI 搜不到 | `tags` 太少 | 补充同义词 |
| 改完没变化 | 浏览器缓存 | `Ctrl + F5` 强制刷新 |

## 发布

改完内容后，告诉负责发布的人，或自己执行：

```bash
git add -A
git commit -m "新增文章：xxx"
git -c http.proxy=http://127.0.0.1:7892 push github master
```

推送后 1–2 分钟线上生效。详见 [06_DEPLOYMENT](06_DEPLOYMENT.md)。

## 内容节奏建议

| 时间 | 加什么 |
|---|---|
| 每完成一项"廉" | 一篇文章 + 相关照片说明 |
| 每场活动后 | 一条情景或案例 |
| 每月 | 1–2 条 AI 知识条目 |

**不要攒到结题**——内容是一次次长出来的，不是一次性写出来的。
