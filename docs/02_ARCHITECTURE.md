# 02 · 系统架构

## 1. 一句话架构

**一个纯静态网站，三种访问方式，零运行时依赖。**

---

## 2. 三条访问路径

```
                    ┌─────────────────────────────┐
                    │   同一份文件（约 160 KB）     │
                    │   index.html + assets/      │
                    └──────────┬──────────────────┘
                               │
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
   ┌────▼─────┐          ┌─────▼─────┐         ┌──────▼─────┐
   │  GitHub  │          │  馆内电脑  │         │  U 盘/备份  │
   │  Pages   │          │ 本地 file://│         │   拷贝      │
   └────┬─────┘          └─────┬─────┘         └──────┬─────┘
        │                      │                      │
   手机扫码访问            触摸屏全屏导览            应急兜底
   （依赖网络）            （断网可用）            （不依赖任何服务）
```

**关键点**：三条路径共用同一份文件，不存在"两份内容需要同步"的问题。

| 路径 | 载体 | 网络 | 谁维护 |
|---|---|---|---|
| 公网 | GitHub Pages | 需要 | 自动同步 |
| 馆内 | 本地文件夹 | **不需要** | 拷贝文件 |
| 兜底 | U 盘 / zip | 不需要 | 手动 |

## 3. 技术选型

| 选择 | 备选 | 为什么选它 |
|---|---|---|
| 纯静态 HTML/CSS/JS | React、Vue、Next.js | 无需构建、无需 Node 环境、断网可用、十年后仍能打开 |
| 哈希路由（`#/article/a1`） | History API | `file://` 协议下 History API 不可用，哈希可以 |
| 原生 DOM 渲染 | 虚拟 DOM | 页面数量少，没必要引入框架 |
| 内容集中在 `data.js` | 每页一个 HTML | 改内容只需动一个文件，降低维护门槛 |
| GitHub Pages | 云服务器、Gitee Pages | 免费、无需备案、无需续费；Gitee Pages 已对个人关闭 |
| 检索式问答 | 接入大模型 API | 无密钥、无网络依赖、每条回答可追溯 |

## 4. 运行时结构

```
index.html
├── <header>         导航（7 个栏目）
├── <main id="view">  ← 所有页面渲染在这里
├── <footer>
└── <div id="searchOverlay">  搜索层
        │
        ├── data.js   提供数据
        ├── ai.js     提供问答
        └── app.js    负责渲染
```

### 启动流程

```
1. 浏览器加载 index.html
2. 依次加载 data.js → ai.js → app.js
3. app.js 读取 location.hash（如 #/article/a1）
4. 调用对应视图函数，生成 HTML 字符串
5. 注入 #view，绑定事件
6. 监听 hashchange，重复 3–5
```

### 为什么用字符串拼接而不是模板引擎

页面数量少、结构稳定，字符串拼接没有额外依赖，且**改样式时不用学新语法**。
代价是代码不如组件化清晰，这在 4 个文件、约 1000 行的规模下可以接受。

## 5. 数据流

```
用户点击
   │
   ▼
app.js 读取 data.js 中的数组（ARTICLES / FIGURES / SCENARIOS / RULES / KB）
   │
   ├── 普通页面 → 生成 HTML → 注入 #view
   │
   └── 廉洁AI → 把问题交给 ai.js → 检索 KB → 返回答案 + 出处 → 注入聊天气泡
```

**没有网络请求，没有后端接口。** 所有数据在页面加载时已经在内存里。

## 7. 导览机模式（kiosk）

同一份网站，加一个 `?kiosk=1` 参数即进入导览模式：

| 行为 | 实现 |
|---|---|
| 全屏无地址栏 | Chrome `--kiosk` 参数 |
| 关闭后自动重开 | PowerShell 循环监听进程退出 |
| 闲置 150 秒回欢迎页 | `app.js` 中的定时器 |
| 防止误退出 | 左上角 72px 内连点 5 次 + 密码 |
| 开机自启 | 启动文件夹快捷方式 → `.vbs` → `.ps1` |

细节见 [07_KIOSK_RUNBOOK](07_KIOSK_RUNBOOK.md)。

## 8. 扩展方向（如果将来要做）

| 需求 | 最小改动 |
|---|---|
| 正文加图片 | 在 `data.js` 的 body 增加一种块类型，`app.js` 增加一个渲染分支 |
| 后台编辑 | 加一个 `admin.html` 表单页，生成 `data.js` 片段 |
| 访问统计 | 插入第三方统计脚本（会破坏"零依赖"，需权衡） |
| 多语言 | 复制一份 `data.js`，按语言切换 |

**不建议**引入框架或构建工具——目前规模下，收益小于维护成本。
